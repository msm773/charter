    Open or Create an Agent Context

    An Agent Context is a dedicated folder agents read: AGENT-CONTEXT.md, .agent-context.json and the governing documents in authoritative/. It may sit inside a project or its own Git repository; nothing else belongs in it.

    Open Agent Context checks the folder and shows whether agents can be served. It writes nothing in the folder, except that an interrupted Charter write is rolled back first.

    Create Agent Context makes a new, empty one in an empty folder. To start from governing documents you already have, put them in authoritative/ and open the folder: Rebuild Agent Context generates the rest.

    Neither action runs Git, or creates agent instruction files such as AGENTS.md or CLAUDE.md.

    Names a new Agent Context; it titles the map agents read.

    A change set is the only way Charter changes what governs: a candidate may govern alongside, revise or replace one governing document you name — which is then archived privately — and a governing document may be withdrawn, returning it to candidate status. Starting from one candidate or document opens a change set with that one outcome; you can add related outcomes before its preview, which you confirm once by typing change governing context.

    A governing document is never edited in place: Revise files a candidate prefilled from it. A document changed with other tools governs once the Agent Context is valid again, and is shown as changed outside Charter.

      Context Map

      Charter generates AGENT-CONTEXT.md, the agents' entry point, and .agent-context.json, its integrity record, from the governing documents and this Agent Context's settings. The map is a routing aid, not a governing document, and is never edited by hand.

      Rebuild Agent Context regenerates both after documents were changed with other tools — an edit, a merge, a recovery. It is offered only when the governing documents are valid and nothing else is in the folder, and it never changes a governing document.

      Agent Proposals

      Agents submit proposals with charter propose --context . in this Agent Context's folder. Each is kept in private local state on this computer, untrusted, until you decide it.

      Accepting a proposal never changes governing context. It files, updates or retires an authority candidate — not context — after a preview. Making a candidate govern is a separate decision, in a change set.

      A proposal is stale when its target changed after the agent read it; it cannot be accepted as written. An agent's name, reason and expected context impact are its own claims.

      Review proposals from agents. Once you accept one, it becomes an authority candidate.

      Settings

      The project name and agent guidance are recorded in .agent-context.json and written into AGENT-CONTEXT.md. Agent guidance is advisory: a governing document's stricter rule always applies.

      Changing a setting is previewed first, and changes no governing document. The map's other wording is generated and cannot be edited.
